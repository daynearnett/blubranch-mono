## Secondary finding: confirms the long-standing "inconsistent id-field naming" watchlist item with a concrete repro

Tried to search `GET /jobs?tradeId=1&state=OH` (the field names `pay-insights` and `POST /jobs`
both use) expecting it to filter to Ray's trade — got back the full unfiltered 13-job catalog
across welder/HVAC/electrician/carpenter/heavy-equipment with zero error. Root cause: the actual
query schema (`jobSearchQuerySchema` in `packages/shared/src/schemas/job.ts`) takes a bare
**`trade`** (slug string, e.g. `"electrician"`), not `tradeId`, and there's no `state` param on
`/jobs` at all — Zod's default object parsing silently strips unrecognized keys instead of
erroring, so a caller using the field names from `pay-insights`/`POST /jobs` gets no filtering and
no warning that anything went wrong. Re-ran with the correct param (`?trade=electrician`) and
got the right 6 results. This is the first concrete, reproducible instance of the long-tracked
"inconsistent id-field naming across routes" watchlist item (previously NOT-RE-TESTED for several
weeks) — worth promoting off the backlog since it has real UX teeth: a client-side bug that used
the wrong param name would silently show every trade's jobs to a worker searching their own, with
no error to signal the mistake.
