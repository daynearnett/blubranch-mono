## Headline: the documented "known constraint" is now wrong for all three workers

The protocol's standing note says every worker should hit `403 PhoneVerificationRequired` on apply.
Today **all three workers (w1, w2, w3) instead got `403 ProfileIncomplete`** with
`missing: [phone, photo]` — none of the three sim worker accounts has a profile photo set (in
addition to the expected missing phone). The apply-readiness gate (CLAUDE.md's Quick-Apply-gate
work) is doing exactly what it's designed to do — when more than just phone is missing it correctly
returns the richer `ProfileIncomplete` shape instead of the legacy phone-only code — but it means
the sim's own "known constraint" documentation no longer matches what these accounts actually
produce, and a dev reading only the headline error code would misdiagnose this as a regression. Not
a bug; a stale assumption. Recommend either adding profile photos to the three worker fixtures (to
match the documented single-constraint scenario) or updating the protocol doc to say
`ProfileIncomplete` is now the expected shape.
