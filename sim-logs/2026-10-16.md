## New finding today: a `new_message` notification can sit unread for almost two months with zero decay

While checking Deb's (e2) notifications for the fresh profile-view/connection-request/vouch activity
from this run, found a `new_message` notification dated **2026-08-19** still `readAt: null`, sitting
underneath today's fresh activity in the same unread list. This is the same lifecycle gap as #8/#8c
(notification state never resolves or expires) but on a different notification type and a much longer
horizon than previously documented (the oldest specific example in the Oct-11 findings doc was 51
days for a `connection_request`; this is closer to 58 days for a `new_message`). Should-fix, same root
cause as #8/#8c/#6 — notifications have no lifecycle beyond creation and an explicit read call.
