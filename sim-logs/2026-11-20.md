## Headline 2 — cold DMs are confirmed, directly from the route code, to be intentionally
unblocked — a genuine design contrast worth documenting, not a gap in the vouch fix

While Deb and Vic were still strangers, **Vic sent Deb a cold DM** (`POST /messages`,
`recipientId`+`content`) — `201`, delivered, conversation created. No connection check at all; the
route (`routes/messages.ts`) only rate-limits non-connection sends to 50/day, confirmed by reading
`checkNonConnectionLimit` inline. So vouches require an accepted connection (Headline 1) but DMs
explicitly don't — by design, per the code comment above the vouch route itself ("gates who may
vouch at all... so a stranger can't fabricate a 'worked together' claim"). Worth stating plainly
for the punch list: this is **not** the "cold-DM gate" the persona-briefing doc's example list
once implied might exist — there is no DM connection gate, and there was never meant to be one
(recruiters messaging workers cold is a legitimate product flow). Filing this as a documentation
clarification, not a bug.
