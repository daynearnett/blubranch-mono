## Headline 1 — big news: four of the watchlist's "should-fix" items are FIXED, confirmed live

Reading the current route code before testing paid off — several fixes have shipped since the
11-08 findings doc and all four verify clean live:

1. **Malformed `:id` → raw Prisma 500 leak, fixed on both `/jobs/:id` and `/companies/:id`.**
   `GET /jobs/not-a-real-uuid` now returns `400 {"error":"BadRequest","message":"Invalid id"}`
   instead of the verbatim Prisma `P2023` exception body reconfirmed as recently as Nov 9.
   `GET /companies/not-a-real-uuid` → same clean `400`. The systemic fix the Nov-08 doc called
   for ("audit all `:id`-param routes in one pass") appears to have landed.
2. **`tradeId`/`state` on `/jobs` no longer silently no-ops.** `GET /jobs?tradeId=1&state=OH` now
   `400`s with `{"error":"ValidationError","issues":[{"path":"","message":"Unrecognized key(s) in
   object: 'tradeId', 'state'"}]}` — the schema is `.strict()` now, with a code comment explaining
   exactly why (a caller using the plausible-but-wrong param name used to get the full unfiltered
   catalog with zero signal). Reconfirmed live.
3. **`pay-insights` trade-slug NaN silent-fallback, fixed.** `GET /jobs/pay-insights?tradeId=electrician`
   now `400`s with `{"error":"BadRequest","message":"tradeId must be a positive integer"}` instead
   of quietly falling back to the caller's own trade. Reconfirmed live (tested via Tommy/plumber,
   the persona the bug used to bite).
4. **`plan` branding, fixed.** `GET /payments/subscription` now returns a new `planLabel` field
   alongside the raw `plan` slug — Deb (e2): `"plan":"pro","planLabel":"Blu"`; Vic (e3):
   `"plan":"unlimited","planLabel":"Blu Max"`. The raw slug is kept (so `hasActiveSubscription`
   etc. still work) but the client now has a branded string to show.
